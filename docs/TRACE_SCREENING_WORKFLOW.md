# 当前 Trace 筛选流程

本文整理截至 2026 年 9 月 21 日已核对的筛选流程及四批次交付口径，供协作者理解候选如何产生、证据如何追溯，以及后续工作从哪里继续。对应实现随本次代码同步提交；原始数据与批次产物保留在本地。批次数字采用 2026 年 9 月 20 日已保存的首次筛选汇总与最终交付快照。

筛选的目标是从真实用户与科研、Coding Agent 的交互中，找到需求有依据、任务有实质挑战、上下文可以还原、完成条件能够明确的候选任务，为后续索取 workspace 和构造评测任务提供输入。一个 session 是原始会话，一个 Trace 是分析轨迹，一个 Episode 是围绕同一目标的任务片段；当前主要按 Episode 打标和筛选，再按原始 session ID 导出会话清单。同一会话可以包含多个不同任务，因此候选案例数与去重会话数分别统计。

流程从预处理开始，将不同来源的会话统一为 Trace、Turn 和 Event，保留用户、助手、工具调用、工具结果与错误的角色、顺序和来源位置。内部生成的标识用于关联和断点续跑，对外交付则使用核验过的原始 session ID，并提供原始会话文件与 workspace 路径。已有预处理和分析结果优先复用，新增标签或筛选规则通常作为独立增量步骤运行，避免因展示或统计变化重新执行全部前置阶段。

用户侧初筛对应 02 阶段，只读取真实用户消息，识别研究范围、初始目标、需求演进和可能值得分析的信号，并将同一目标组织成 Episode。用户的澄清、纠正、返工、重复强调或阻塞可以成为进一步验证的线索，但不直接证明 Agent 失败。初筛也不以会话长度、轮数或是否出现明显不满作为单一门槛，后来新增的要求不能倒推成 Agent 起初就应知道的约束。

Agent 行为验证对应 03 阶段，对初筛选出的候选回读相关助手回复、工具事件、错误和必要的后续结果，核对目标是否清晰、实际行为与交付是否满足要求，以及观察到的问题由 Agent、环境、外部服务或需求变化中的哪些因素造成。验证保留原文依据和证据不足之处，不能将记录结束当成未执行，也不能将助手声称完成当成工具执行成功。04 阶段再以本地规则合并初筛和验证结果，形成 confirmed、review、excluded 等历史痛点结论；05 阶段负责报告展示。历史痛点结论和后续优先候选结论是不同判断。

当前四批次的 06 阶段以 04 中 confirmed 和 review 的记录为入口，对同一 Episode 的原始交互进行增量打标，保留历史结论。原始事件按已保存且有效的 Episode 边界恢复，并区分必要的片段后续上下文；缺失或无效边界进入异常记录，不能用零散引用位置的最小值、最大值猜测任务范围。长输入可使用分块索引和按位置取回原文的机制，记录选取范围、补充取证及未阅读全文的限制；超过上限仍须显式报错，不能静默截断，也不能把索引机制正常运行等同于证据召回完整。

打标描述任务目标、具体需求、约束及来源、研究领域、工作对象、难度、失败与反馈，以及需求和子需求的分类关系。新版使用需求和子需求描述科研活动，不再单列历史科研阶段标签。需求以用户实际表达为依据，同时允许模型阅读助手和工具上下文，以理解用户接续上一轮回复提出的要求。当前提示要求在同一次打标中先识别具体用户需求，再粗配父需求、细配子需求，并核对分类表中的父子关系；Agent 自行选择的操作不能自动升级成用户需求。需求是否提出、来源是什么、是否核心以及是否完成分别判断，任务未完成不等于需求本身缺乏依据。难度按任务的推理、协作和验证负担判断，不能从对话长短或 Agent 成败反推。

标签由具体判断和原文证据支撑。claim_id 标识一项判断，保存其目标、理由和支持状态；evidence_id 标识一条可定位的原文，关联事件、角色、引文及来源位置。二者是文件内部的关联编号，不能互相替代。程序校验标签结构、枚举、字段路径、分类关系及证据引用，并检查引文能否对应原始事件；模型给出的 supported 表示该模型认为有依据，不等于人工确认。阅读用的 review_view 可以展开标签、理由与证据，但筛选规则中的引用是否展开仍取决于对应导出版本。

获得有效标签后，独立筛选步骤复用标签和相关原文，先核验结构与引用有效、选集范围匹配，以及不存在影响筛选的未解决关键冲突，再执行 S1 至 S4。S1 要求至少一个前 33 类主需求及其具体子需求有支持证据，辅助需求不能单独作为入选依据；S2 要求任务难度为有证据支持的 medium 或 high；S3 核验能否还原同一个连贯任务的要求；S4 核验能否从用户要求及相关输出、测试或指标明确完成条件。S3、S4 包含模型语义核验，不能仅因字段非空就通过，也不能从分类表的通用验收说明替案例发明完成标准。这一步不会重新进行整套语义打标。

全部前置检查与 S1 至 S4 通过时，结果为 priority_candidate，即优先候选；没有已核实排除原因、但仍有待查项时，结果为 review；经核实不符合要求或选集范围时，结果为 not_selected。当前通用筛选不额外要求历史痛点必须为 confirmed，也不将 Agent 最终失败作为独立必过门槛。优先候选表示适合继续索取材料和评估任务构造价值，不表示 Agent 执行成功、人工验收通过或 workspace 已经可复现。必要输入、起始代码与数据、环境配置和材料可获得性，留到 workspace 获取后单独核验。

运行中将正常待复核与流程异常分开记录。打标失败、无效 Episode 边界、上下文超限或筛选引用错误都需要保留原因及受影响案例，不能直接当作原始 Trace 不合格。已验证的通用修复包括唯一且归属一致时的字段路径纠正、需求编号与判断编号纠正，以及核对完整事件编号和连续原文后补登记证据；这些处理保留修复记录，不自动改变语义结论或把部分支持提升为充分支持。客户端还支持启用有限次数的 503 退避、持久化重试预算和连续失败冷却。成功结果逐条保存、可断点续跑，仅处理受影响项；技术错误修好后仍须按正常规则筛选，不能直接算作入选。

各批次保存标签、证据、来源、模型核验、筛选结果、检查点与版本信息，机器产物位于 workspace/analysis-runs，报告和供审阅的会话清单位于 docs/高质量Trace筛选_20260915。跨批汇总采用明确的输入快照，记录规则、分类表与文件哈希，并分别统计主需求、全部需求、具体子需求和 high 难度案例；报告中的 hard 就是已有 high 标签。分布只计入关系合法且有充分支持的映射，同一案例可命中多个类别，类别计数不能相加当作候选总数。会话导出按 session ID 去重，保留所关联的案例与各批来源；模型字段从来源记录关联，标准化名称之外保留原始标识。

已保存的四批首次筛选综合报告覆盖 20260813、20260828、20260820 和 20260822，分别有 10、43、167、560 条优先候选，合计 780 条 Episode、672 个去重会话，其中 high 难度为 260 条。该口径包含补筛及技术错误修复，排除第三批正常二次复核新增的 5 条。随后按交付要求去掉一个混合模型会话，最终带模型字段的合并 JSONL 为 779 条候选、671 个会话；原综合报告仍保留 780 条统计口径，两者不能混用。该快照仍列有 123 条打标失败和 58 条边界异常，合计 181 条流程异常。已经接入通用修复并完成离线验证，不代表这些剩余案例已补跑完成；后续优先处理异常并完成首次筛选，正常待复核条目的二次复核维持暂停，新增候选经核验后再形成新的交付版本。
